See Kumoss in action

Watch a real, unscripted Kumoss session: a plain-language request becomes an applied pull request, and a risky delete is blocked until an administrator reviews it.

demo
video
walkthrough

This page shows Kumoss working on a real cloud environment, from a developer’s first request to an applied change, and then a destructive request that Kumoss holds for review. Watch the four-minute video, then use the walkthrough below to jump to the guide behind each moment.

About this recording

  • One unscripted session. The run was recorded against a real cloud subscription with the default Kumoss stack. Waiting times are shortened; the generated code, plans, reports, and applied results are not edited.

  • Captions and step cards are added in editing. They explain what happens on screen while the agent works.

  • Sensitive data is blurred. Subscription identifiers, accounts, and user names are masked. The request was typed in Spanish and is shown in English; Kumoss accepts requests in the language your team uses.

  • The notification cards are a recreation. They follow the messages Kumoss sends when it locks a session; in the recording, those messages went to a chat channel off screen.

Customize prompts

Drift fixed on the way. Kumoss finds network rules that were changed outside the code and updates the code to match, in the same pull request.

Remediate drift

A plan that passes. Kumoss runs a real OpenTofu or Terraform plan, feeds any errors back to the agent, and audits the result for compliance.

Generate infrastructure

A report anyone can read. The summary, the impact, and the estimated monthly cost, followed by the explanation of the drift fix and the generated code.

Follow a session

2:00

Pull request and apply. The developer opens the pull request, approves it, and confirms the apply. Kumoss applies exactly the plan that was reviewed.

Merge and apply

Live in the cloud. The new resources appear in the cloud console, and every agent step is recorded as a trace.

Monitor with Phoenix

Rules defined once. The platform team keeps its security and architecture rules as versioned prompts that apply to every request.

Customize prompts

2:46

A destructive request. The same developer asks to delete the storage account. Kumoss flags the change as high impact.

Generate infrastructure

3:08

Deployment blocked. The deletion breaks policy, so the session is locked and apply is refused, whoever asks. The platform team is notified.

If the session is locked

3:27

Humans approve. An administrator with the editor role reviews the locked session in the admin panel and removes the lock.

Session locks

Reviewed, applied, recorded. The developer applies the reviewed plan, and the resources are removed with a full audit trail.
